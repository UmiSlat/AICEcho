# 实验支线收尾与 3.0 整合

更新：2026-10-10。当前仍为 3.0 预览，不代表正式发布或所有设备可用。

本轮完成本地保存、整合与验证，尚未推送 GitHub，也未打包或安装新 APK。

## 已达成的目的

- 在一台 Xiaomi 15 Pro / Android 16 / HyperOS / 主用户 CE 环境中，完成 AOSP/Shizuku 运行时基线、身份写入、NFC 重载、启用、实际回滚与 HINATA 射频验证。
- 保留实体卡原 IDm 和原始块数据，移除固定或派生的兼容 IDm 路线。
- 支持 CE/DE 计划和归档，避免把身份表写到两个存储域；DE 目前仅有本地测试。
- 卡片备份、导入导出和完整详情保留；普通页面平铺，技术参数及实验探测集中到高级模式。

具体包版本、结果和证据限制见 [3.0 验收](3.0_ACCEPTANCE.md)。本机有 Root/LSPosed，不能据此宣布干净无 Root 部署已通过。

## 分支处理

| 分支 | 用途 | 处理方式 |
| --- | --- | --- |
| `main` | 后续统一开发与构建 | 接收整合结果，保留主线 CI 和签名发布流程 |
| `feat/3.0-integration` | 本次整合检查 | 从主线建立，合并实验成果；不改写已有历史 |
| `codex/hcef-rootless-experiments` | 完成的实验路线 | 收尾提交 `9211052`，冻结保存，不再长期双线维护 |
| `feat/main-progress-archive-20261010` | 旧主线工作目录存档 | 提交 `fa62d3f` 完整保存原未提交改动，不将旧兼容算法重新带入产品 |

实验存档标签使用 `archive/hcef-rootless-20261010`，不使用触发发布流程的 `v*` 名称。分支及标签先保存在本地；是否已上传应以远端为准。

新功能与修复从主线建立短期 `feat/` 或 `fix/` 分支。旧版通过已有标签和 Release 保留，不新增长期 2.2 维护线。

## 整合边界

- 应用实现以实验线当前版本为准，主线重复移植的代码不重复叠加。
- GitHub Actions 使用 JDK 21；保留主线测试、Lint、APK 构建、产物检查及签名发布配置。
- Lab 源码和历史研究资料保留在 `tools/hcef-lab`，不自动执行，也不变成普通用户的必经步骤。
- 对话记录、私有设备证据、构建产物和签名材料不进入提交。
- 本次整合不安装手机、不启动游戏、不改钱包，不创建正式发布标签。

本地整合验证：40 个测试 suite、662 项通过、4 项因未提供可选私有样本而跳过，无失败或错误；Lint 无错误、19 条既有提示。工作流 YAML、文档链接和提交文件范围已核对；GitHub 托管构建尚未运行。

## 接下来的验收

| 项目 | 当前状态 | 下一步 |
| --- | --- | --- |
| 新 UI 与高级模式 | 本地 UI 回归通过，尚未安装 | 打包预览版，检查普通模式全流程及键盘/底部布局 |
| 原卡身份、写入和回滚 | code 49 的 CE 闭环及 HINATA 已通过 | 新包复验，不把旧包截图当新 UI 验收 |
| 本机游戏账号 | 当前版本尚未验证 | 验证原 IDm 进入本人账号，排除读卡器直接读取手机等混杂因素 |
| 冷重启后启用 | 未验证 | 重启后按正常入口重新启用并刷卡 |
| DE、其他 ROM / 芯片 | 未实机验证 | 收集环境与能力检查结果，按证据补适配 |
| 应用分身 / 工作资料 / 次用户 | 运行时预置未支持 | 暂不扩大支持声明 |

下一版打包需使用高于本地 code 49 的版本号，并核对 debug/正式签名的覆盖条件；不能直接卸载已有卡片数据的应用。

完成新界面、账号和重启验收后，再决定 3.0 正式发布。其他设备适配可以继续迭代，但必须明确已验证环境，不将单机成功写成通用兼容。
