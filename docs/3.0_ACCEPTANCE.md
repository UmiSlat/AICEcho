| 步骤 | 实际结果 |
| --- | --- |
| 准备独立合成卡 | `RUNTIME / PREPARED / CE`，仅改变本应用一条登记；不是兼容 IDm 模式 |

| 合成身份射频 | HINATA Lite 的 `FFFF/88B4` 找到预期 IDm，PMm `00F1000000014300`、System Code `88B4`、块 `00/82/85` 均匹配 |

正向系统恢复由用户明确确认；回滚返回较快，未单独观察到第二次系统确认页，因此不把两次确认界面均已观察当作证据。回滚成功依据是重载后的完整登记和原卡 RF/块数据，而不是恢复退出码。两次模拟均使用独立 `:nfc_session` 入口，没有为修复旧 Binder 重启整个应用或重复恢复。

## 日常流程

1. 选中已保存的卡片。卡片内容、备份格式和原 IDm 不因升级改变。
2. 在“状态 → 模拟方式”选择 Shizuku 或 Root 模块。新安装默认 Shizuku，已有安装保留原设置。
3. 已配置的卡片直接点“开始模拟”，保持刷卡页在前台。启用只核对已保存的身份，不重新写入，也不要求 Shizuku 持续运行。
4. 首次配置或换卡时点“配置卡片”，连接 shell 模式的 Shizuku，再按页面完成准备、系统确认写入、读回和单独重载。
5. 退出刷卡页停止模拟。进入配置页不会自动恢复数据或重载 NFC。

普通界面隐藏原始 NFC 参数、来源、存储域、快照和 Lab。需要排查时，在设置开启高级模式，配置页会直接显示“高级诊断”，不再另套折叠入口。卡片页集中开始/配置操作，状态页不重复；能力页的详细备份与运行时探测也只在高级模式显示。Root 模块路线保留原有行为；Shizuku 路线不会自动查询 Root/PMm 状态。此界面整理为 code 49 实测之后的改动，已随 3.0.1 打包发布，尚未安装到手机，不用旧截图验收新布局。

## 计划找回

应用或 UserService 正常结束后，重新连接可选择“继续上次配置”。它读取私有保存记录并按来源重新读取当前登记，只重建状态，不自动写入或重载。未完成步骤在普通模式提供此入口，已结束计划的手动找回在高级模式提供。仍未完成的同次开机操作不能据此解除阻止；准备新计划会替换原计划。

## 验收顺序

1. 同 debug 证书覆盖安装，核对全部卡片、选择、原始数据及模式保留。不要卸载旧应用。
2. 不写入身份，直接启用现有原卡，核对 HINATA 的原 IDm、88B4、PMm 及 00/82/85。
3. 另获许可后重载 NFC，再次启用；核对主进程和 UserService 不被重启，模拟子进程更新，计划仍可用。
4. 再单独验证计划找回、回滚和卡片切换；涉及系统恢复由本人确认。新版还需核对实际 CE/DE 文件位置与计划相同，正向和回滚只写对应域；包默认 Context 以外的厂商存储布局另行确认。
5. 最后验证目标读卡器/游戏账号、无钩子环境及重启后的稳定性。

2.2.23 的旧后端证据保留为历史，不能替代当前 AOSP 验收。code 49 已取得本机 CE 的新身份写入、实际回滚、独立模拟进程和 HINATA 往返证据；其他 ROM、DE、目标账号、进程中断找回及重启后的稳定性仍需独立验证。

## Shizuku 会话恢复修复（2026-10-13，源码）

用户反馈 Shizuku 方式偶发“页面显示正在模拟，但贴紧读卡器仍无响应”，重启手机后恢复；同设备的 Root 方式未遇到该问题。故障时的日志和射频状态未保存，不能确定是前台路由、框架缓存还是 HAL 状态所致。

源码确认原模拟页只在 `onResume` 启用，没有监听 NFC 开关或持续检查已保存的登记，成功提示可能过期。修复加入前台只读检查、NFC 开关恢复、有限服务重试和手动“重新连接”；不重新写身份、不调用 Root、不自动重启系统 NFC。页面区分等待刷卡、收到请求和未生成回应，高级模式提供无卡号的请求/回应统计。

这部分修改已包含在 `3.0.1` / code 51 发布 APK 中，不包含在 `v3.0.0` / code 50 的预发布 APK 中，尚未安装到手机。本地用例覆盖正常检查不打断读卡、关闭/开启 NFC、服务中断及超时、身份变化、暂停取消和请求反馈；实际故障仍需复现验收。

下一次遇到无响应时，先移开手机再点“重新连接”；仍无效则停止并重新开始模拟，让独立会话进程重建，再尝试关闭/开启 NFC。记录当时的页面状态、是否收到请求和每一步恢复结果，必要时再采集系统 NFC 日志。不要以重新应用卡片配置作为默认排障动作。

## 自动连接与配置向导（2026-10-13，源码）

本轮将“保存资料”“配置到手机”和“开始模拟”分开。卡片页按实时登记显示一个主操作，并区分“已选中”与“已配置到手机”；未完成配置优先提供继续入口。系统暂时无法查询时，进入独立模拟进程再次检查，不直接要求重新写入。

配置页普通模式显示“检查设备 → 应用配置 → 加载核对 → 完成”。已经运行且获得授权的 Shizuku 会自动连接；首次授权仍需点击。只有用户发起“配置并使用”后才开始准备，并在必要时处理初始合法登记；系统恢复与 NFC 重载仍分别确认。详细参数、快照、手动步骤和回滚移到高级模式。Root 注册与卡片数据格式未改。

这些改动先完成本地源码与回归验证，随后纳入 3.0.1 发布 APK；尚未进行这一版本的手机安装、系统写入或射频验收。实机下一轮重点：

1. 已授权时重新打开配置/设备检查页自动连接，未授权时不自动弹授权。
2. 已配置的同一卡在 Shizuku 未运行时仍可直接开始模拟。
3. 保存读取结果或选择另一张卡不改系统登记；配置按钮才启动向导。
4. 首次登记、系统恢复取消、加载核对与换卡的提示准确，失败不显示完成。
5. 返回或旋转不重复检查/写入；中断后显示继续配置，保留原卡与已保存计划。
