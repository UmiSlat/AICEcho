# AICEcho

AICEcho 是一款面向 Amusement IC / Aime 卡片的 Android 管理与 NFC-F 模拟应用。读取并保存实体卡资料后，可以在支持的手机上模拟刷卡。

支持多张卡片管理、实体卡读取和本地备份。日常使用从选卡开始，高级参数和诊断工具可按需开启。

名称中的 `AIC` 取自 Amusement IC，`Echo` 表示回应：保留原卡标识，卡片资料由用户本地保存和使用。

本页介绍当前版本的安装与使用方式，下载入口见下文。

AICEcho 原名 AimeSimulator。已发布的 3.0.1 安装包仍使用旧名称，后续构建采用 AICEcho；包名、签名和卡片备份格式沿用旧版，继续支持覆盖升级和导入旧备份。

## 我的手机能用吗？

先按你要做的事情判断：

| 你想做什么 | 需要什么 |
| --- | --- |
| 保存、编辑、导入或导出卡片资料 | Android 10 及以上，不需要 Root，也不需要开启 NFC |
| 从实体卡读取资料 | 在上面的基础上，手机有 NFC，且能读取这张卡 |
| 通过 Shizuku 配置手机刷卡 | Android 14 及以上，支持 NFC-F 卡片模拟；在手机主空间中使用，没有额外用户、应用分身或工作资料；安装并通过调试方式启动 Shizuku 13 或更新版本 |
| 已有 Root，使用模块方式刷卡 | Android 10 及以上、支持 NFC-F 卡片模拟，以及可用的 LSPosed；按[模块设置教程](docs/ROOT_SETUP.md)配置 |

安装包目前提供 ARM64 版本，最低支持 Android 10。

安装后可在“状态 → 设备兼容性”查看“卡片模拟支持”。手机需要支持 NFC-F 主机卡模拟（HCE-F）才能模拟刷卡；读取、管理和备份可单独使用。手机钱包可用并不代表支持 HCE-F。

设备和读卡器的兼容性见下方[兼容性说明](#兼容性说明)。

## 下载与安装

| 版本 | 下载位置 | 说明 |
| --- | --- | --- |
| 正式版 3.0.1 | [下载页面](https://github.com/UmiSlat/AimeSimulator/releases/tag/v3.0.1) | 在资源列表中下载 `AimeSimulator-3.0.1-release.apk`；可选兼容补丁与校验文件也在同一页面 |
| 3.0 主线测试版 | [Android CI](https://github.com/UmiSlat/AimeSimulator/actions/workflows/android-ci.yml) | 选择成功的 `main` 构建，在 Artifacts 下载 `AICEcho-release-…`，解压后安装 APK；下载需登录 GitHub |

主线测试版使用与正式版相同的证书签名，版本名带有 `-ci` 和提交标识，可在“设置 → 关于”查看。它包含开发中的更新；日常安装优先选择正式版。`v3.0.0` 保留为此前的预发布，不覆盖旧标签或旧安装包。

更新前建议导出卡片备份。同签名且版本码不低于已安装版本的 APK 可覆盖更新；本地 debug 包可能使用不同签名，请保留数据，不要直接卸载重装。

## 第一次使用

以下使用 **Shizuku 方式**配置。Shizuku 用于提供系统调试权限，配置时不要求给本应用 Root 权限。首次配置或换卡时需要连接；配好后，日常刷同一张卡无需保持 Shizuku 运行。

### 1. 检查手机

开启手机 NFC，打开“状态 → 设备兼容性”，确认手机支持卡片模拟。

尚未添加卡片时，页面会提示先选卡。

### 2. 读取并保存卡片

1. 在“卡片”页点“添加卡片 → 读取卡片”。
2. 把实体卡贴近手机 NFC 天线，保持不动，等待读取结果。
3. 点“使用此数据”，给它起一个容易认出的名字，保存并选中。

已有备份的话，可点“添加卡片 → 导入备份”，再选中要用的卡片；“设置 → 卡片数据”也保留导入与导出入口。

**IDm** 是卡片的电子标识，读取后会自动填入。**Access Code** 是卡面印刷的 20 位号码，只用于记录和显示，可以留空。使用读取结果时，保留原始卡片参数即可。

### 3. 配置手机刷卡

1. 从[官网下载 Shizuku](https://shizuku.rikka.app/zh-hans/download/)，按[官方启动教程](https://shizuku.rikka.app/zh-hans/guide/setup/)选择“通过无线调试启动”。这里不要选择“通过 Root 启动”；也可以按教程通过电脑调试启动。
2. 在 AICEcho 的“状态 → 模拟方式”中选择“Shizuku”。
3. 回到“卡片”页，点“配置并使用”。首次使用时点“授权 Shizuku”；已有授权会自动连接并检查，不必每次重进应用都手动连接。
4. 配置页会依次显示“检查设备 → 应用配置 → 加载核对 → 完成”。检查与初始登记由应用处理；出现“应用配置”时，确认后在系统恢复页点“恢复我的数据”，密码留空。
5. 点“加载配置”，确认短暂重启 NFC，等待核对完成。这一步通常不需要重启手机，期间 NFC 和钱包会短暂不可用。
6. 完成后点“开始模拟”。

页面只显示当前需要的操作。配置中断时，首页会显示“继续完成配置”；遇到失败可进入“设备兼容性”检查。详细参数、快照与回滚工具放在高级模式内。

### 4. 开始刷卡

在“卡片”页选中要用的卡。首页会检查手机当前登记：已经配置好的卡显示“开始模拟”；换成另一张尚未配置的卡时显示“配置并使用”。选中卡片不会自动更改手机登记。

点“开始模拟”后，保持刷卡页打开、手机解锁，将手机 NFC 天线贴近读卡器。

没反应时，可调整手机方向和位置，或去掉厚手机壳，让 NFC 天线贴近读卡器。

刷卡结束后返回上一页，模拟就会停止。以后使用同一张卡，直接“选卡 → 开始模拟”；换卡或修改电子标识后，再做一次配置。

“已选中”表示当前选择，“已配置到手机”表示 Android 当前登记与这张卡一致；保存卡片资料并不等于完成手机配置。

## 常见问题

### 只有卡面号码，能恢复丢失的卡吗？

不能。卡面 20 位号码不是完整的卡片资料，也不能据此算出电子标识。推荐在实体卡还在手里时读取并导出备份。

### 读取结果没有 Access Code，还能保存吗？

可以。卡面号码是可选信息。读到电子标识不一定代表已取得完整卡片资料，建议读取原卡并保留读到的数据。

### 老式 Aime 卡、门禁卡也能模拟吗？

当前手机刷卡方式面向 FeliCa 类型的 Aime 配置，不是通用门禁卡模拟器。老式 MIFARE Aime 有读取卡号的实现，但没有旧卡实测，也不能直接用这种方式模拟；本应用不提供写入实体白卡的功能。

### 提示需要配置，或者系统拒绝卡片标识怎么办？

先检查“状态 → 模拟方式”。Shizuku 方式需要先完成“配置到手机”；模块方式需要启用正确的模块并重启，详见[模块教程](docs/ROOT_SETUP.md)。

配置失败时，先按提示处理，再通过“设备兼容性”确认原因。反馈问题时请附手机型号、Android 版本、应用版本和提示文字；需要更多信息时可开启高级模式。

### 要不要把它设为默认 NFC 应用？

不是所有手机都需要，先保持原设置。应用提示确实需要切换时，再到“状态”页操作；用完可以点“恢复手机钱包”，在系统页面重新选择原钱包。

### 高级模式是做什么的？

高级模式用于查看完整卡片参数、系统登记和诊断信息，日常刷卡无需开启。它只影响信息展示，不会改变卡片数据或设备兼容性。

## 备份卡片

到“设置 → 卡片数据”点导出，得到一个包含全部已保存卡片资料的 JSON 文件。换手机时可导入这个文件；导入前可以预览，并选择合并或替换。

资料只保存在本机，应用没有在线账号、自动云同步或网络权限。

## 兼容性说明

目前已在 Xiaomi 15 Pro / Android 16 / HyperOS 上验证卡片配置、切换、恢复及 HINATA 读卡，读到的卡片资料与原配置一致。该设备安装了 Root/LSPosed，尚未在完全未 Root 的手机上复验；3.0 的游戏账号识别、重启后使用、其他机型和部分系统存储方式仍需验证。

设备检查显示支持、配置成功或读卡器读到数据，分别代表不同步骤通过，并不保证所有游戏或机台都能使用。详细结果见 [3.0 验收记录](docs/3.0_ACCEPTANCE.md)。

## 注意事项与项目声明

- 将本应用设为默认 NFC 应用会替换原来的手机钱包，可能影响碰一碰支付。使用结束后可通过“状态 → 恢复手机钱包”恢复。
- 配置期间重新启动 NFC 会短暂中断刷卡，请等操作结束后再使用读卡器。
- 备份文件是明文，可能包含真实卡号；完整性校验不是加密。备份、完整详情截图和诊断日志请私密保存。
