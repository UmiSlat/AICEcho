# AimeSimulator

把实体 Aime 卡的资料保存在 Android 手机里，在支持的手机上用手机刷卡。

你可以用它读取、管理和备份卡片资料，也可以导入已有备份。日常使用不需要填写高级参数。

**当前正在开发 3.0，新界面尚未打包发布。下面介绍的是 3.0 的使用流程；已发布的旧版请参考对应发布说明。**

## 我的手机能用吗？

先按你要做的事情判断：

| 你想做什么 | 需要什么 |
| --- | --- |
| 保存、编辑、导入或导出卡片资料 | Android 10 及以上，不需要 Root，也不需要开启 NFC |
| 从实体卡读取资料 | 在上面的基础上，手机有 NFC，且能读取这张卡 |
| 用手机刷卡，走推荐的 Shizuku 方式 | Android 14 及以上，支持 NFC-F 卡片模拟；在手机主空间中使用，没有额外用户、应用分身或工作资料；安装并通过调试方式启动 Shizuku 13 或更新版本 |
| 已有 Root，使用模块方式刷卡 | Android 10 及以上、支持 NFC-F 卡片模拟，以及可用的 LSPosed；按[模块设置教程](docs/ROOT_SETUP.md)配置 |

安装包目前只提供 ARM64 版本，适用于近年的主流 Android 手机，不提供 32 位或 x86 版本。

**怎么知道支持“卡片模拟”？** 安装后打开“状态 → 设备能力检查”，看“卡片模拟支持”。如果显示“此设备不支持 NFC-F 主机卡模拟”，就不能用这台设备走本应用的手机刷卡方式；读取和备份功能仍可单独使用。能用手机钱包，不等于支持这里需要的卡片模拟。

**目前测到哪一步了？** Xiaomi 15 Pro / Android 16 / HyperOS 已通过卡片配置、切换和恢复，并在 HINATA 读卡器上读到与原配置相同的卡片资料。当前 3.0 的游戏账号和重新开机后的使用还在待测列表。其他机型可以按下面的步骤检查和尝试，暂时没有通用的支持机型清单。测试机已安装 Root/LSPosed，尚未在完全未 Root 的手机上复验。

## 下载与安装

已发布的 APK 在 [GitHub Releases](https://github.com/UmiSlat/AimeSimulator/releases)。打开对应版本的资源列表，下载以 `.apk` 结尾的文件，在手机上打开安装。

3.0 新包发布后会放在同一位置。找不到下面介绍的按钮时，先在“设置 → 关于”检查版本，不要把旧版界面当作 3.0。

## 第一次使用

下面以推荐的 **Shizuku 方式**为例。Shizuku 是帮助应用取得系统调试权限的工具，这条配置方式不要求给应用 Root 权限。首次配置卡片时需要它；配好后，日常刷同一张卡不要求它一直运行。

### 1. 检查手机

开启手机 NFC，打开“状态 → 设备能力检查”。确认“卡片模拟支持”不是“不支持”。

这时提示还没有选择卡片是正常的，下一步再添加。

### 2. 读取并保存卡片

1. 在“卡片”页点“添加卡片 → 读取卡片”。
2. 把实体卡贴近手机 NFC 天线，保持不动，等待读取结果。
3. 点“用于卡片配置”，给它起一个容易认出的名字，保存并选中。

已有备份的话，可直接到“设置 → 卡片数据”导入，再选中要用的卡片。

编辑时看到的 **IDm** 是卡片的电子标识，读取后会自动填入，不需要自己编写。**Access Code** 是卡面印刷的 20 位号码，只用于记录和显示，可以留空。其他参数暂时不用管。

### 3. 配置手机刷卡

1. 从[官网下载 Shizuku](https://shizuku.rikka.app/zh-hans/download/)，按[官方启动教程](https://shizuku.rikka.app/zh-hans/guide/setup/)选择“通过无线调试启动”。这里不要选择“通过 Root 启动”；也可以按教程通过电脑调试启动。
2. 在 AimeSimulator 的“状态 → 模拟方式”中选择“Shizuku”。
3. 回到“卡片”页，点“配置卡片 → 连接 Shizuku”，允许授权。
4. 点“准备当前卡片”。如果页面出现“创建初始配置”，先完成它。
5. 页面出现“写入卡片配置”时点击确认；手机弹出恢复页面后，点“恢复我的数据”，密码留空。
6. 写入完成后点“重载 NFC”。这里的“重载”就是重新启动手机的 NFC 功能，通常不需要整机重启。
7. 页面允许“启用卡片模拟”后，即可继续刷卡。

**按页面当前显示的步骤操作即可。** 如果配置已经存在，会直接允许启用，不需要再走一遍写入。先不要开启高级模式，也不必运行“完整备份”或 Lab 测试。

### 4. 开始刷卡

在“卡片”页选中要用的卡，点“开始模拟”。保持刷卡页打开、手机解锁，将手机 NFC 天线贴近读卡器。

没反应时，先移动一下位置、横放手机或去掉厚手机壳。测试机使用 HINATA 时，需要横放并贴紧读卡器。

刷卡结束后返回上一页，模拟就会停止。以后使用同一张卡，直接“选卡 → 开始模拟”；换卡或修改电子标识后，再做一次配置。

## 常见问题

### 只有卡面号码，能恢复丢失的卡吗？

不能。卡面 20 位号码不是完整的卡片资料，也不能据此算出电子标识。推荐在实体卡还在手里时读取并导出备份。

### 读取结果没有 Access Code，还能保存吗？

可以。对于当前手机模拟使用的 FeliCa 卡，卡面号码是可选的，不会自动从读取结果生成。读到电子标识不等于读到所有资料；首次使用优先读取原卡并保留读到的数据，不要随意修改。

### 老式 Aime 卡、门禁卡也能模拟吗？

当前手机刷卡方式面向 FeliCa 类型的 Aime 配置，不是通用门禁卡模拟器。老式 MIFARE Aime 有读取卡号的实现，但没有旧卡实测，也不能直接用这种方式模拟；本应用不提供写入实体白卡的功能。

### 提示需要配置，或者系统拒绝卡片标识怎么办？

先检查“状态 → 模拟方式”。Shizuku 方式需要先完成“配置卡片”；模块方式需要启用正确的模块并重启，详见[模块教程](docs/ROOT_SETUP.md)。

配置页报错时先处理页面给出的原因，不要反复写入。记录手机型号、Android 版本、应用版本和提示文字，排查时再开启高级模式查看详情。

### 要不要把它设为默认 NFC 应用？

不是所有手机都需要，先保持原设置。应用提示确实需要切换时，再到“状态”页操作；用完可以点“恢复手机钱包”，在系统页面重新选择原钱包。

### 高级模式是做什么的？

给排查问题和研究使用，普通刷卡可以保持关闭。它显示额外的卡片参数和诊断工具，不会因为打开而让原本不支持的手机变得支持。“卡片 → 详情”仍可查看完整的已保存资料。

## 备份卡片

到“设置 → 卡片数据”点导出，得到一个包含全部已保存卡片资料的 JSON 文件。换手机时可导入这个文件；导入前可以预览，并选择合并或替换。

资料只保存在本机，应用没有在线账号、自动云同步或网络权限。

## 注意事项与项目声明

- **更新前先导出备份。** 测试包和正式包可能使用不同签名，不能直接互相覆盖；不要为了安装而直接卸载有数据的旧应用。
- 将本应用设为默认 NFC 应用会替换原来的手机钱包，可能影响碰一碰支付。测试结束后可通过“状态 → 恢复手机钱包”恢复。
- 配置期间重新启动 NFC 会短暂中断刷卡，请等操作结束后再使用读卡器。
- 备份文件是明文，可能包含真实卡号；完整性校验不是加密。备份、完整详情截图和诊断日志请私密保存。
